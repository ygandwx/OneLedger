# 项目：个人财务记录系统（单人自用，快速上线版）

## 0. 工作原则
- 先把本文档保存为 docs/SPEC.md。按第 6 节的步骤推进，每步完成后保证可运行，git 提交，简要汇报后继续。
- 目标是尽快可用：优先端到端跑通，界面简洁即可，不要过度设计，不要引入本文档之外的功能和依赖。
- 数据结构按第 3 节一次设计完整（以后改结构代价大），界面可以先做最简单的版本。
- 不确定的地方按最合理的理解实现，记录到 docs/DECISIONS.md，不要停下来等待。
- 界面使用简体中文，适配手机浏览器。

## 1. 目标
单人使用的网页应用：记录我个人和我管理的多家公司在各类网站上的支出（一个网站可有多个账号），管理支付工具（卡、钱包）及其状态和额度，管理订阅与公司年度事项并提醒，存储公司档案与文件，按月、季、年汇总。

## 2. 技术栈
- Next.js（App Router）+ TypeScript + Prisma + SQLite（WAL 模式）
- Tailwind + shadcn/ui（列表直接用 shadcn 的 Data Table），图表用 Recharts
- 金额计算用 decimal.js
- 定时任务：在 Next.js 的 instrumentation 中启动 node-cron，不单独做 worker
- 部署：docker-compose，两个服务：app 和 caddy（自动 HTTPS），数据放在 /data 卷
- 配置全部走环境变量，提供 .env.example

## 3. 数据模型
约定：币种用 ISO 代码（CNY、USD、GBP、EUR、HKD、SGD、JPY）；金额以最小货币单位的整数存储（JPY 0 位小数，其余 2 位）；时区可配置，默认 Asia/Shanghai；有关联记录的数据只能归档，不能物理删除。

- 主体：类型（个人/公司）、名称、默认币种、备注、是否归档。
- 公司档案（公司主体一对一）：全称、注册地、注册编号、成立日期、注册地址、办公地址、财年结束日（月-日）、董事和股东（文本）、秘书公司、备注。
- 支付工具：所属主体、类型（信用卡/借记卡/虚拟卡/PayPal/支付宝/微信/银行账户/其他）、昵称、发卡行或平台、卡号后四位（只允许 4 位数字）、币种、有效期、状态（正常/冻结/挂失/停用/已注销/已过期）、替换为（新卡）、信用额度、账单日、还款日、年费、年费日期、备注。另建状态变更日志（原状态、新状态、日期、原因）。
- 网站：名称、网址、备注。
- 账号：网站、所属主体、账号标识（登录邮箱/用户名/ID）、状态、备注。不存密码。
- 绑卡记录：账号、支付工具、开始日期、结束日期（为空表示当前）。
- 分类：名称（预置：云服务器、域名、软件订阅、广告、手续费、公司注册与合规、其他）。
- 支出记录：交易日期、网站、账号（可空）、支付工具、付款主体（默认为卡的所属主体）、归属主体（默认为账号的所属主体）、原币金额与币种、入账金额与币种、外汇手续费、订单号/交易流水号、分类、状态（待确认/已入账/已退款/未扣款）、退款关联（退款为独立的负数记录）、关联的周期事项、发票状态、垫付是否结清、汇率覆盖值、备注、附件、软删除标记。
- 周期事项（订阅和公司年度事项共用一个模型）：类型（订阅/年报/年审/税务申报/地址续费/秘书费/其他）、标题、所属主体、关联网站/账号/支付工具（可空）、预计金额与币种（可空）、周期（一次性/每月/每季/每年/每 N 月）、下次到期日、提前提醒天数（可多个，默认 7、1）、是否到期自动生成待确认支出、状态（有效/暂停/已取消）、备注。
- 文件：所属主体、分类（营业执照/章程/年报/合同/发票收据/其他）、标题、到期日（可空）、关联支出或周期事项（可空）、存储路径、原文件名、大小、上传时间。
- 汇率：日期、基准币种、目标币种、汇率、来源（自动/手动）。
- 通知：关联事项、到期日、提前天数、渠道、发送时间、是否已读（设唯一约束防止重复发送）。

## 4. 功能
1. 登录：首次启动在初始化页面创建唯一账号，之后关闭入口。密码用 argon2 哈希，强制 TOTP 双重验证，登录失败限速，所有页面、API、文件下载都要鉴权。
2. 基础资料：主体、公司档案、支付工具、网站、账号、绑卡的增删改查。支付工具改为非正常状态时，列出仍绑定在它上面的账号和有效订阅，可批量换绑到另一张卡。
3. 支出录入：先选账号，自动带出网站、当前绑定的卡、付款主体、归属主体、币种和上次的分类；支持“复制上一条”；退款按钮生成关联的负数记录；可上传附件。列表支持按日期、主体、网站、账号、卡、分类、状态筛选。
4. 汇率：每天从 Frankfurter API（https://api.frankfurter.dev/v2，免费、无需 key，开发前请查阅最新文档）抓取汇率；按交易日期的汇率折算，当天没有汇率时取之前最近一天的；支持手动录入和单条覆盖。
5. 报表：期间可选月/季/年/自定义；主体可多选，显示方式为合并汇总或分主体并列；币种显示可选“按币种分别合计”或“折算为指定币种”；默认按归属主体统计，可切换为按付款主体；可按网站、账号、卡、分类分组；按月趋势图；另有垫付未结清汇总；可导出 CSV。金额口径为入账金额加手续费，退款冲减，不计待确认和未扣款记录。
6. 周期事项与提醒：每天 09:00（可配置）检查到期情况。对开启自动生成的事项，生成待确认的支出记录并把下次到期日推进一个周期（31 日在小月取月末）。信用卡还款日、年费日、卡片到期、文件到期也要提醒。提醒渠道为站内通知和 Telegram 机器人，同一天的提醒合并成一条消息发送，设置页有发送测试按钮。
7. 首页：未来 30 天到期事项、待确认扣款（可确认金额或标记未扣款）、仍有绑定的停用卡、本月和本年支出合计。
8. 文件：上传到 /data/uploads，文件名使用随机 UUID；PDF 和图片可在线预览；只能通过鉴权路由下载；单个文件上限 25MB。
9. 备份：每天用 VACUUM INTO 备份数据库，并打包 uploads 目录，保留最近 30 份；README 写清恢复步骤。

## 5. 测试（只写这几类）
金额与最小单位转换、汇率回退与交叉汇率、周期日期推算（月末、闰年）、还款日跨月推算、报表汇总口径。

## 6. 开发步骤
1. 骨架：脚手架、登录与 TOTP、布局，并立即写好 docker-compose 和 Caddy 配置，确保能部署到 VPS。
2. 基础资料与支出录入、汇率。
3. 报表、CSV 导出、每日备份（完成到这一步即可正式开始使用）。
4. 周期事项、提醒（站内通知和 Telegram）、首页仪表盘。
5. 公司档案页面与文件管理。
